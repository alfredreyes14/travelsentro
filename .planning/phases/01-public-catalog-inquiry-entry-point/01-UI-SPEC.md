## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge inline padding |
| sm | 8px | Compact element spacing (list item internal gaps) |
| md | 16px | Default element spacing (card padding, form field gaps) |
| lg | 24px | Section padding (within a package detail section) |
| xl | 32px | Layout gaps (between major page sections) |
| 2xl | 48px | Major section breaks (between itinerary/inclusions/FAQ blocks) |
| 3xl | 64px | Page-level spacing (hero to content, footer separation) |

Exceptions: Icon-only tap targets (WhatsApp/Facebook icon buttons in compact card layouts on mobile) use a **44px minimum touch target**, per WCAG 2.5.5 / iOS HIG — this is not on the 8-point scale itself but is a padding/min-height override applied to otherwise 8-pt-scaled icon buttons.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 (Inter regular) — use 600 only for emphasis (badges, "From ₱X" tag) | 1.4 |
| Body | 16px | 400 (Inter regular) | 1.5 |
| Heading | 20px | 600 (Plus Jakarta Sans semibold) | 1.2 |
| Display | 28px | 600 (Plus Jakarta Sans semibold) | 1.2 |

Only 2 weights used system-wide: **400 (regular)** for body/label text, **600 (semibold)** for all headings and emphasis. Do not introduce 300, 500, or 700 anywhere in this phase.

- **Display (28px)**: package name on detail page (`<h1>`), page-level hero heading on the package list page.
- **Heading (20px)**: section headings within a package detail page ("Itinerary", "What's Included", "Trip Facts", "FAQ"), card title on package list cards.
- **Body (16px)**: itinerary day descriptions, FAQ answers, form field values, general paragraph copy.
- **Label (14px)**: form field labels, meta text (duration, group size), checklist item text (inclusions/exclusions/what-to-bring), nav links.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FAF7F2` (warm off-white / sand) | Page background, package detail body surface |
| Secondary (30%) | `#0E5C63` (deep ocean teal) | Header/nav bar, footer, package card imagery overlay scrim, section dividers |
| Accent (10%) | `#F5793A` (sunset coral/orange) | See explicit reserved-for list below |
| Destructive | `#DC2626` (red) | Not used in this phase (public browse/inquire only — no delete/edit actions exist here). Declared now for visual consistency with Phase 2+ admin panel. |

Accent (`#F5793A`) reserved for:
- "Send Inquiry" form submit button (primary CTA on both per-package and Contact Us forms)
- "From ₱X" price emphasis text/badge on package list cards and detail page
- "Featured" badge/ribbon on featured packages (PKG-05 will populate this in Phase 2; Phase 1 renders the badge if seed data marks a package featured)
- Active/selected state on FAQ accordion trigger and active nav link underline

**Explicit third-party brand exceptions (not part of the 60/30/10 accent budget):**
- WhatsApp CTA button uses WhatsApp's own brand green `#25D366` — this is a recognized affordance users already associate with WhatsApp contact actions; using the accent color instead would reduce recognizability.
- Facebook CTA button uses Facebook's own brand blue `#1877F2` — same rationale.

Both exceptions apply only to these two specific buttons; no other element may borrow WhatsApp green or Facebook blue.

## Copywriting Contract

| Element | Copy |
|---------|------|
| WhatsApp CTA | "Message us on WhatsApp" (icon + label; icon-only on compact card, full label on detail page) |
| Facebook CTA | "Message us on Facebook" (icon + label; icon-only on compact card, full label on detail page) |

| Empty state body (package list) | "Check back soon, or reach out to us directly on WhatsApp or Facebook — we're happy to help you plan your trip." (Note: unlikely to trigger with seed data always populated in Phase 1, but must render correctly for when Phase 2 unpublishes all packages.) |
| Error state (form submission failure) | "Something went wrong sending your inquiry. Please try again, or reach us directly on WhatsApp or Facebook." |
| Error state (field validation, react-hook-form + zod) | Field-specific, concise: "Please enter your name" / "Enter a valid email address" / "Enter a valid phone number" / "Please add a short message" |
| Destructive confirmation | Not applicable — Phase 1 has no destructive actions (public-facing browse + inquire only; no delete/edit UI exists until Phase 2). |
