<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Supabase Postgres (anon key) | Package list query runs client-invisible (server-side RSC) but is scoped by the same anon-key RLS as any public caller |
| Browser → next/image → Supabase Storage | Image Optimizer proxy-fetches Storage-hosted photos on the visitor's behalf |
| Browser → wa.me / Facebook | Pure outbound navigation, no data returned to our app |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-12 | Information Disclosure | `app/(public)/packages/page.tsx` query | medium | mitigate | `.eq('is_published', true)` enforced server-side in the query itself (not a client-side filter over an unfiltered fetch) — an unpublished/draft package can never appear in the list response even if RLS alone would have allowed reading it |
| T-01-13 | Tampering (SSRF-adjacent) | `next/image` fetching Storage URLs | low | accept | Already mitigated at the `next.config.ts` layer in `01-01` (pathname scoped to `/storage/v1/object/public/package-photos/**`); this plan only consumes that existing configuration, introduces no new exposure |
| T-01-14 | Repudiation / low-severity UX | Outbound WhatsApp/Facebook links missing `rel="noopener noreferrer"` | low | mitigate | Both CTA components explicitly set `target="_blank" rel="noopener noreferrer"` to prevent the opened tab from gaining a `window.opener` reference back into the TravelSentro tab |

</threat_model>
