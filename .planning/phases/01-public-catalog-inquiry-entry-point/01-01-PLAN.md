<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm install → local filesystem | Third-party package code executes at install/build time |
| next.config.ts → Next.js Image Optimizer | Configured remote hostname/pathname controls what the Image Optimizer will proxy-fetch |
| .env.local → git history | Local secrets must never enter version control |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-SC | Tampering | npm installs (`next`, `typescript`, `@supabase/*`, `react-hook-form`, `zod`, `lucide-react`, etc.) | high | mitigate | Install only the exact package+version list from RESEARCH.md's Standard Stack table, already cleared by RESEARCH.md's Package Legitimacy Audit (no `[SLOP]`, all `[SUS]` flags resolved as false positives from an official org repo); explicitly pin `typescript@5.9.3` to avoid silently drifting onto the unverified 7.x line |
| T-01-01 | Tampering | `next.config.ts` `images.remotePatterns` | medium | mitigate | Hostname wildcard (`*.supabase.co`) is offset by a tightly-scoped `pathname: '/storage/v1/object/public/package-photos/**'` so the Image Optimizer cannot be tricked into proxy-fetching arbitrary Supabase-hosted content outside this bucket's public objects |
| T-01-02 | Information Disclosure | `.env.local.example` / future `.env.local` | medium | mitigate | Only the template file (no real values) is committed; `.gitignore` verified to exclude `.env*.local`; `SUPABASE_SERVICE_ROLE_KEY` documented as server/CLI-only, never `NEXT_PUBLIC_*`-prefixed, so it can never end up in the browser bundle |

</threat_model>
