<objective>
Polish the admin dashboard sidebar's tap targets and open/close feel (D-05), add a consistent shadow/elevation cue to the shared `Card` primitive (D-07), and verify/document that D-07's hover/focus/active interactive-state requirement is already satisfied by existing shadcn defaults for the sidebar chrome and remaining table rows — entirely within the existing locked brand system (D-06) — no new colors, fonts, or component logic.

Purpose: `components/ui/sidebar.tsx`'s `SidebarProvider`/`Sheet`-backed mobile drawer is already functionally correct (D-05 confirms reuse, polish-only). Its default `SidebarTrigger` (28px) and `SidebarMenuButton` (32px) sizes are below this codebase's established 44px touch-target convention (already used for the drag-handle button in `package-list-row.tsx`). Separately, RESEARCH.md's Pitfall 4 found `components/ui/card.tsx` has no `shadow-*` utility at all, unlike `dialog.tsx`/`dropdown-menu.tsx`/`select.tsx`, which already use `shadow-md`/`shadow-lg` for floating surfaces — this plan closes that inconsistency for the static, in-flow `Card` primitive without inventing a new elevation scale. Finally, D-07 locks "hover/focus/active interactive states" as an in-scope polish target; Task 3 makes explicit (rather than silently assumed) that `SidebarTrigger`/`SidebarMenuButton` and every remaining desktop `TableRow` already ship complete hover/focus-visible/active styling via their existing shadcn base classes, so no redundant styling is added on top of working defaults.
Output: `app/admin/(dashboard)/layout.tsx` with larger sidebar tap targets and a polished header; `components/ui/card.tsx` with a subtle added shadow; SUMMARY.md documenting the hover/focus/active-state determination for sidebar chrome and table rows.
</objective>
