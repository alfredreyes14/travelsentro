<objective>
## Phase Goal

**As a** TravelSentro Admin or Staff member, **I want to** have every customer inquiry automatically captured as a tracked CRM lead — with the customer instantly acknowledged and my team instantly notified — and be able to view, search, and manage those leads, **so that** no inquiry is ever lost and I can follow up efficiently.

(Same phase-level user story as 03-01-PLAN.md.)

## This Plan

Build the project's first Route Handler — `app/api/inquiries/route.ts` — as the single write path every public inquiry submission goes through (D-01), and rewire `components/inquiry/inquiry-form.tsx` to POST to it instead of calling `submitToFormspree()` directly from the browser. This is the vertical slice that makes CRM-01 real end-to-end: a customer fills out the existing form → the CRM gets the lead first (via 03-01's `record_inquiry()` RPC) → Formspree gets a best-effort backup copy afterward, never blocking or failing the customer's response (D-02). No emails are wired yet — AUTO-01/AUTO-02 land in 03-03, which extends this same Route Handler.

Purpose: Deliver the phase's core reliability guarantee — the CRM write no longer depends on Formspree's uptime or the client's tab staying open — and prove idempotency (AUTO-03) live, not just in code review.
Output: A working `/api/inquiries` POST endpoint, an updated inquiry form, and a live verification script proving idempotency, honeypot handling, and RLS scope on the actual running server.
</objective>

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-05 | Denial of Service | Public unauthenticated POST /api/inquiries used for spam/flooding | medium | mitigate | Server-side honeypot check (_gotcha, silently succeeds without writing), zod length caps on name/message/phone (200/5000/30 chars) prevent oversized payload abuse; full IP-based rate limiting is explicitly deferred as a post-launch fast-follow per 03-RESEARCH.md's own Security Domain guidance (not mandated by CONTEXT.md, no rate-limiting infra in the current stack) |

| T-03-08 | Repudiation / Tampering | Accidental double-click or genuine redelivery creating duplicate leads | high | mitigate | Client-generated requestId (stable across a double-click, rotated only after a successful submit) + record_inquiry()'s ON CONFLICT (request_id) DO NOTHING; is_new gates the Formspree forward — verified live by Task 3's idempotency check |
