<objective>
## Phase Goal

**As a** TravelSentro Admin or Staff member, **I want to** securely log into an admin panel and manage the tour package catalog according to my individually-assigned permissions, **so that** the business can keep its live package catalog accurate and control exactly who can change it, without needing a developer for every update.

(Same phase-level user story as prior Phase 2 plans — this is a gap-closure plan, not a new phase.)

## This Plan

Closes 02-UAT.md Test 7 (cosmetic): "Use #021f4a for primary and #f49314 for secondary." Root cause is not a bug — the brand hex values hardcoded in `app/globals.css` (`--primary: #f5793a`, `--secondary: #0e5c63`) simply no longer match what the user wants. This is a direct token-value update, not an investigation.

**Scope note carried from 02-UAT.md's gap analysis, applying even though Test 7 was scored during an admin-panel visual pass:** `--primary`/`--secondary` are global CSS custom properties consumed by both the Phase 2 admin panel (sidebar, buttons, switches) and the already-shipped Phase 1 public site (header/nav/footer, "From ₱X" badges, Featured badge, Send Inquiry CTA, FAQ accordion active state). Changing them re-colors both. The user gave explicit, unambiguous hex values with no stated exception for the public site, so this plan applies the change globally rather than gating it behind a checkpoint.

During file-audit for this plan, one additional file was found to hardcode the OLD secondary hex directly rather than going through the CSS variable: `components/packages/checklist.tsx`'s `ICON_COLORS` map uses `text-[#0E5C63]` (a Tailwind arbitrary value) for the "included" and "bring" checklist icons on the Phase 1 package detail page. Updating `app/globals.css` alone would leave these two icons visibly stuck on the old teal while every other themed element moves to the new orange — this plan fixes that drift at its source by switching to the already-available `text-secondary` Tailwind utility (used everywhere else in this codebase, e.g. `app/(public)/layout.tsx`'s header/footer) instead of hardcoding a second literal hex value.

Purpose: Make the admin panel (and, transitively, the public site) match the business's actual current brand colors, and remove the one hardcoded-hex drift point found during this fix so it can't recur on the next color change.
Output: `app/globals.css`, `components/packages/checklist.tsx`, and both Phase 1/2 UI-SPEC.md docs updated to the new hex values.
</objective>
