<objective>
## Phase Goal

**As a** TravelSentro Admin or Staff member, **I want to** securely log into an admin panel and manage the tour package catalog according to my individually-assigned permissions, **so that** the business can keep its live package catalog accurate and control exactly who can change it, without needing a developer for every update.

(Same phase-level user story as prior Phase 2 plans -- this is a gap-closure plan, not a new phase or a new vertical slice.)

## This Plan

Closes 02-VERIFICATION.md round 6 gap 2 / 02-REVIEW.md's CR-01: photo uploads fail for realistic photo file sizes as part of creating/editing a package (PKG-01/PKG-02, D-11). Confirmed by direct, deterministic source inspection (not a runtime state transition requiring a live test): `next.config.ts` never overrides Next.js's default 1 MB Server Action request-body limit, and `components/admin/photo-manager.tsx`'s `handleFilesSelected` reads every selected file into a base64 string and sends the **entire batch** of files in a single `uploadPhotos()` Server Action call. Base64 encoding adds ~33% overhead over the raw file size, so a single ~750 KB photo -- well below what a phone camera or DSLR typically produces -- already exceeds the unmodified 1 MB limit, and multi-file selections multiply this further.

This plan applies both halves of 02-REVIEW.md CR-01's own suggested fix together (not an either/or): raise the Server Action body size limit to a realistic value, AND stop batching every file into one oversized request. Doing both is more robust than either alone -- raising the limit without chunking still caps out on large multi-file batches; chunking without raising the limit still fails on a single realistically-large photo.

Purpose: Make PKG-01/PKG-02's photo-upload capability (D-11) actually work for real-world photo sizes, not just small test fixtures.
Output: `next.config.ts` with a raised `experimental.serverActions.bodySizeLimit`; `components/admin/photo-manager.tsx` sending one Server Action call per selected file instead of one oversized batched call.
</objective>
