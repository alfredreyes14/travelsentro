# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized — `components.json` present from Phase 1, no init gate needed) |
| Preset | `style=base-nova`, `base-color=neutral`, `css-variables=true`, RSC enabled — base-ui/react primitives, not classic Radix |
| Component library | `@base-ui/react` primitives (via shadcn/ui base-nova style) |
| Icon library | `lucide-react` (already installed, used for drag handles, action icons, nav icons) |
| Font | Headings: **Plus Jakarta Sans** (`--font-heading`, `next/font/google`) — Body: **Inter** (`--font-body`, `next/font/google`). Both already wired in `app/layout.tsx`; no new font work this phase. |

**Layout posture:** The admin panel is an internal staff tool (2-5 person team, per CLAUDE.md). Design desktop-first, but keep usable down to 768px (tablet) — sidebar collapses to an icon rail or sheet below that width using shadcn's `sidebar` component's built-in responsive behavior. Sub-768px phone support is not a hard requirement for this phase (unlike Phase 1's public site, which had PUBL-09 as an explicit requirement) — do not spend effort hand-tuning phone layouts for admin screens.

**Brand continuity note:** No new brand assets were supplied since Phase 1. This phase reuses the exact color tokens already committed to `app/globals.css` (see Color section) — it does not introduce a second palette for the admin panel.

## Spacing Scale

Declared values (must be multiples of 4) — unchanged from Phase 1, reused for consistency across the whole app:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge/switch inline padding |
| sm | 8px | Compact spacing (table cell padding — shadcn `Table` default `p-2` already matches this), drag-handle-to-row-content gap |
| md | 16px | Default element spacing (form field gaps, dialog padding, sidebar item padding) |
| lg | 24px | Section padding (within a package edit form section, card padding on list pages) |
| xl | 32px | Layout gaps (between major page sections: header → filters → table) |
| 2xl | 48px | Major section breaks (between package form tabs' content and page header) |
| 3xl | 64px | Page-level spacing (rarely needed in admin's denser layout; reserve for empty-state vertical centering) |

Exceptions:
- Icon-only tap targets (drag handles, row action icons, sidebar collapse toggle) use a **44px minimum touch target**, per WCAG 2.5.5 — same exception as Phase 1, applied here to `@dnd-kit` drag handles and table row icon buttons.
- Table row density: use shadcn `Table`'s default cell padding (`p-2` / 8px) rather than a looser card-style 16px — admin lists (packages, users) should read as compact data, not marketing cards.

## Typography

Unchanged from Phase 1 — same 4 declared sizes, same 2 weights, reused for visual continuity between public site and admin panel:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 (Inter regular); 600 for emphasis (table column headers, switch/toggle labels, active nav item) | 1.4 |
| Body | 16px | 400 (Inter regular) | 1.5 |
| Heading | 20px | 600 (Plus Jakarta Sans semibold) | 1.2 |
| Display | 28px | 600 (Plus Jakarta Sans semibold) | 1.2 |

Only 2 weights used system-wide: **400 (regular)** and **600 (semibold)**. Do not introduce 300, 500, or 700 anywhere in this phase.

- **Display (28px)**: not typically needed in the admin panel's denser UI — reserve for the login page's brand/welcome heading only.
- **Heading (20px)**: page titles ("Packages", "Users"), package edit form section titles (Details / Itinerary / Photos / Inclusions & FAQ), dialog titles (Add Package, Add Staff Account).
- **Body (16px)**: form field values, table cell content, dialog body copy.
- **Label (14px)**: form field labels, table column headers, sidebar nav item text, switch/permission toggle labels, meta text (created date, last edited by).

## Color

Reused directly from `app/globals.css` (already implemented in Phase 1 — not re-declared here as new tokens, only extended with an admin-specific mapping note below):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FAF7F2` (warm off-white / sand) | Admin page background, card/table surfaces |
| Secondary (30%) | `#0E5C63` (deep ocean teal) | **Admin sidebar background** (new this phase — see mapping note), section dividers |
| Accent (10%) | `#F5793A` (sunset coral/orange) | See explicit reserved-for list below |
| Destructive | `#DC2626` (red) | Delete package, deactivate account — buttons and confirmation dialog text/icon |

**Sidebar token mapping (new this phase):** shadcn's `sidebar` component reads its own `--sidebar` / `--sidebar-foreground` / `--sidebar-primary` / `--sidebar-accent` tokens, which currently sit at generic shadcn gray defaults in `app/globals.css` (unused until now — Phase 1 had no sidebar). To keep the admin panel visually continuous with the public site's header/nav/footer (which already use the Secondary teal), update these tokens in `app/globals.css`:
- `--sidebar` → `#0E5C63` (same as `--secondary`)
- `--sidebar-foreground` → `#FAF7F2` (same as `--secondary-foreground`)
- `--sidebar-accent` (hover/active row background within the sidebar) → a lighter teal tint, e.g. `oklch(from #0E5C63 calc(l + 0.12) c h)` or a simple `color-mix(in oklch, #0E5C63 85%, white)` — exact value is an implementation detail, but must stay visibly darker than the accent orange so the active nav indicator (below) remains the only orange element in the sidebar
- `--sidebar-primary` (active/selected nav item indicator) → `#F5793A` (the accent), consistent with Phase 1's "active nav link underline" accent usage

Accent (`#F5793A`) reserved for, in this phase:
- Primary submit buttons: "Log In", "Add Package", "Create Package" / "Save Changes" (package form), "Add Staff Account" / "Save Changes" (user form), "Send Reset Link", "Set New Password"
- Active/selected sidebar nav item indicator (Packages vs Users)
- Switch "on" state (Published toggle, Featured toggle, per-staff permission toggles) — shadcn's `switch` component defaults its checked state to `bg-primary`, which already resolves to this accent — no custom override needed, just don't recolor it
- "Featured" badge on the package list (same badge component/copy as Phase 1's public-facing featured badge)

No new second semantic color is needed beyond the existing Destructive red — this phase's only destructive actions (soft-delete package, deactivate account) both map to it.

**Component usage notes (new components, this phase):**
- `sidebar` — admin shell nav (Packages, Users per D-14); permission-based sections hidden entirely per D-13, not disabled
- `table` — package list (with `@dnd-kit` sortable rows for PKG-06, inline `switch` cells for PKG-04/PKG-05) and user/account list
- `switch` — publish/unpublish (PKG-04), featured (PKG-05), and per-staff permission toggles (AUTH-04)
- `select` — role dropdown (Admin/Staff) in account create/edit forms
- `alert-dialog` — delete package and deactivate account confirmations only (see Copywriting Contract; photo delete does not use this)
- `dropdown-menu` — per-row action menu on package/user table rows (Edit, Delete/Deactivate)
- `tabs` — organizes the package create/edit form into Details / Itinerary / Photos / Inclusions & FAQ sections, keeping each `useFieldArray` block (D-12) from turning into one overwhelming scroll
- `skeleton` — `loading.tsx` boundaries for package/user list Server Components during data fetch
- `tooltip` — labels icon-only buttons (drag handle, row action icons) for clarity, pairs with the 44px touch-target exception above
- `form` (existing, hand-authored wrapper) — reused unchanged for all admin forms (login, forgot/reset password, package, account), same `Form`/`FormField`/`FormControl`/`FormMessage` pattern as Phase 1's inquiry form
- `sonner` (existing) — toast feedback for Server Action success/failure across all admin mutations, supplementing inline error copy above
