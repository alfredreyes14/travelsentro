<objective>
## Phase Goal

**As a** TravelSentro Admin or Staff member, **I want to** securely log into an admin panel and manage the tour package catalog according to my individually-assigned permissions, **so that** the business can keep its live package catalog accurate and control exactly who can change it, without needing a developer for every update.

(Same phase-level user story as prior Phase 2 plans — this is a gap-closure plan, not a new phase.)

## This Plan

Closes 02-UAT.md Test 5 (major): "There is no save or publish button. Just create package, nothing happens when I click it." The debug session at `.planning/debug/create-package-button-noop.md` root-caused this to two compounding defects in `components/admin/package-form.tsx`/`components/ui/tabs.tsx`, both confirmed via direct code tracing (not guessed): (1) `form.handleSubmit(onSubmit)` has no `onInvalid` second argument, so a failed Zod validation silently updates `formState.errors` and never runs `onSubmit`'s toast/redirect/persistence logic — zero observable feedback; (2) the shadcn-style `TabsContent` wrapper sits on Base UI's `Tabs.Panel`, whose `keepMounted` defaults to `false` and is never overridden, so a tab that hasn't been visited yet is never mounted at all — meaning a required field on an unvisited tab (most likely `bestTimeToGo`/`groupSize`, both on the crowded "Inclusions & FAQ" tab) can never render its `FormMessage` error text even if the user did switch there.

This plan does not touch `package-form-schema.ts`'s validation rules (already confirmed correct via direct resolver testing in the debug session) or `onSubmit`'s create/update logic (unchanged, already correct).

Purpose: Make an already-correct validation/submit pipeline actually visible and reachable to the user, closing PKG-01's "create a new tour package" UAT gap.
Output: A package-create/edit form that always gives the user visible feedback on submit — either a successful create/save, or a toast plus an automatic jump to the tab containing the first validation error.

**Also unblocks 02-UAT.md Test 6** (photo upload/reorder/delete), which was reported `blocked` only because no package could ever be created to attach photos to. No code change is needed for photo upload itself — once this fix lands, Test 6 should be re-attempted by the user as part of the end-of-phase human verification pass (see this plan's Task 1 `<verify><human-check>`).
</objective>

This pairs with the auto-tab-switch above: once `setActiveTab` makes a tab active, its already-mounted `FormMessage` error text becomes visible immediately, with no first-visit mount flash.
