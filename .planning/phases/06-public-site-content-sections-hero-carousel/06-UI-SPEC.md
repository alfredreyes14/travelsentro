## Spacing Scale

Declared values (must be multiples of 4) — unchanged from Phase 1/2, reused for consistency across the whole app:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, star-rating icon gaps, carousel dot-to-dot gaps |
| sm | 8px | Compact spacing (badge/link inline padding, logo grid gaps in Partners/Clients row) |
| md | 16px | Default element spacing (value prop card padding, testimonial card padding, form field gaps) |
| lg | 24px | Section-internal padding (space between a section's heading and its content grid) |
| xl | 32px | Layout gaps (grid column/row gaps: value props grid, testimonials grid, featured packages grid) |
| 2xl | 48px | Major section breaks (vertical padding between one homepage section and the next, e.g. Why Choose Us → Featured Packages) |
| 3xl | 64px | Page-level spacing (hero carousel to first content section; Brand Partners/Corporate Clients band top/bottom padding) |

Exceptions:
- Icon-only tap targets (carousel prev/next arrows, carousel dot indicators, admin drag handles for slide/testimonial/partner reorder) use a **44px minimum touch target**, per WCAG 2.5.5 — same exception as Phase 1/2. Carousel dot indicators render visually small (8px) but must sit inside a 44px-tall/wide invisible hit area.
- No other exceptions.

## Typography

Unchanged from Phase 1/2 — same 4 declared sizes, same 2 weights, reused for visual continuity across public site and admin panel:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 (Inter regular); 600 for emphasis (star-rating `aria-label` is not visible text; use for meta text, admin table content, button labels) | 1.4 |
| Body | 16px | 400 (Inter regular) | 1.5 |
| Heading | 20px | 600 (Plus Jakarta Sans semibold) | 1.2 |
| Display | 28px | 600 (Plus Jakarta Sans semibold) | 1.2 |

Only 2 weights used system-wide: **400 (regular)** for body/label text, **600 (semibold)** for all headings and emphasis. Do not introduce 300, 500, or 700 anywhere in this phase.

**New-element mapping for this phase (no new sizes introduced):**
- **Display (28px)**: Each homepage section's main title — "Why Choose Us", "Featured Packages" (or equivalent), "What Our Customers Say", hero carousel slide headline/overlay text. Matches Phase 1's precedent of Display = "page-level hero heading."
- **Heading (20px)**: Card-level titles within a section — individual value-prop card title, testimonial customer name, hero slide sub-CTA label if styled prominently.
- **Body (16px)**: Value-prop description text, testimonial quote text, hero slide subheading text, featured-packages section intro copy (if any).
- **Label (14px)**: Admin `/admin/content` table/list row text, form field labels in new admin CRUD dialogs, meta text (sort order, created date).

Accent (`#F49314`) reserved for, in this phase:

No new second semantic color is needed beyond the existing Destructive red.

**Explicit non-accent zones:** Brand Partners / Corporate Clients logos render on their own images (client-supplied artwork) against the Secondary navy band — do not apply accent tinting/filters to third-party logos.

## Section Layout & Composition

Homepage section order (top to bottom), per CONTEXT.md's Claude's Discretion recommendation, confirmed as this phase's default:

1. **Hero Carousel** — full-bleed, `aspect-video` (16:9) on desktop, taller ratio (`aspect-[4/5]` or similar) on mobile if the reused package photo crops poorly; Secondary navy gradient scrim (bottom-to-top or left-to-right) behind overlay text for legibility over any photo; Display-size headline + Body-size subheading + Accent CTA button; autoplay via `embla-carousel-autoplay` (5s delay, `stopOnInteraction: true`, pauses on hover/focus, respects `prefers-reduced-motion` per RESEARCH.md Pitfall 6/Pattern 1); `CarouselPrevious`/`CarouselNext` (44px touch targets) always visible for manual/keyboard control.
2. **Why Choose Us** (value props) — Dominant background, 3-4 column responsive grid (`grid-cols-1 sm:grid-cols-2 lg:grid-cols-4`), each value prop on a Card surface (`--card` white) per the existing Card-on-Dominant-background pattern already used for package cards; title (Heading) + description (Body); no icon field this phase (per RESEARCH.md Assumption A2 — text-only cards).
3. **Featured Packages Grid** — reuses `<PackageCard>` unchanged, same responsive grid as the existing `/packages` list page (no new card component); Display-size section heading ("Featured Packages"); query limited to `is_featured = true, is_published = true`, capped (RESEARCH.md example uses `limit(6)`).
4. **Testimonials** — Dominant background, 3-column responsive grid (`grid-cols-1 md:grid-cols-3`), each testimonial on a Card surface; `Avatar` component (photo if present, initials fallback if not, per RESEARCH.md Assumption A1) + Heading-size customer name + star rating row (Accent-filled `StarIcon`s) + Body-size quote text.
5. **Embedded Inquiry Form** — `<InquiryForm />` reused with zero new props/styling (D-05); inherits Phase 1's `01-UI-SPEC.md` inquiry-form contract verbatim (Accent "Send Inquiry" button, existing validation/error copy). Section heading uses Display size, consistent with the other sections above it.
6. **Brand Partners** — Secondary navy background band, horizontal logo row/grid (`flex flex-wrap` or `grid`), each logo optionally link-wrapped; renders only when ≥1 entry exists (D-07) — fully absent from the DOM otherwise, not an empty-state placeholder.
7. **Corporate Clients** — identical treatment to Brand Partners, independently conditional (RESEARCH.md Pitfall 3 — never combine the two visibility checks).

All section headings (except the two conditional logo bands, which need no heading beyond a small Label-size eyebrow like "Our Partners" / "Our Corporate Clients" if any) follow the same vertical rhythm: `2xl` (48px) top padding separating one section from the previous, `lg` (24px) gap between heading and content grid.

## Copywriting Contract

### Public Homepage

| Element | Copy |
|---------|------|
| Section heading — Why Choose Us | "Why Choose Us" |
| Section heading — Featured Packages | "Featured Packages" |
| Section heading — Testimonials | "What Our Customers Say" |
| Section heading — Contact Form | "Get in Touch" (or reuse existing Contact Us page heading if establishing continuity is preferred by the executor) |
| Section eyebrow — Brand Partners | "Our Partners" |
| Section eyebrow — Corporate Clients | "Trusted By" |
| Hero slide CTA (package-type slide, default) | "View Package" |
| Hero slide CTA (promo-type slide) | Admin-set `cta_label` field; if empty, hide the CTA button entirely rather than rendering an empty button |
| Featured Packages "View All" link (optional, links to `/packages`) | "View All Packages" |

### Admin — `/admin/content`

| Element | Copy |
|---------|------|
| Sidebar nav item | "Content" (permission-gated on `can_manage_packages`, same pattern as "Packages"/"Users") |
| Page title | "Homepage Content" |
| Tab labels | "Hero Slides" / "Why Choose Us" / "Testimonials" / "Partners & Clients" |
| Primary CTA — Hero Slides tab | "Add Slide" |
| Primary CTA — Why Choose Us tab | "Add Value Prop" |
| Primary CTA — Testimonials tab | "Add Testimonial" |
| Primary CTA — Partners & Clients tab | "Add Partner" and "Add Client" (two independent buttons, one per sub-list within the tab) |
| Submit button — create mode (all 4 CRUD forms) | "Add {Slide / Value Prop / Testimonial / Partner / Client}" |
| Submit button — edit mode (all 4 CRUD forms) | "Save Changes" (matches Phase 2's exact convention) |
| Empty state — Hero Slides | Heading: "No hero slides yet" / Body: "Add a photo or promotional slide to feature on the homepage carousel." (CTA: "Add Slide") |
| Empty state — Why Choose Us | Heading: "No value props yet" / Body: "Add a reason customers should choose you — this appears in the homepage's \"Why Choose Us\" section." (CTA: "Add Value Prop") |
| Empty state — Testimonials | Heading: "No testimonials yet" / Body: "Add a customer quote and rating to build trust on the homepage." (CTA: "Add Testimonial") |
| Empty state — Partners / Clients (each independently) | Heading: "No {partners / clients} yet" / Body: "Add a logo to display in the homepage's {Brand Partners / Corporate Clients} section. This section stays hidden on the public site until at least one is added." (CTA: "Add {Partner / Client}") |
| Error state — any CRUD save failure | "Something went wrong saving your changes. Please try again." (reused verbatim from Phase 2's exact convention) |
| Error state — field validation (react-hook-form + zod) | Field-specific, concise, same pattern as Phase 1/2: "Please enter a headline" / "Please upload an image" / "Rating must be between 1 and 5" |
| Destructive confirmation — delete hero slide | Title: "Delete this slide?" / Body: "This slide will be removed from the homepage carousel immediately." / Confirm: "Delete Slide" (destructive-styled) |
| Destructive confirmation — delete value prop | Title: "Delete this value prop?" / Body: "\"{title}\" will be removed from the homepage immediately." / Confirm: "Delete" (destructive-styled) |
| Destructive confirmation — delete testimonial | Title: "Delete this testimonial?" / Body: "This testimonial from {customer name} will be removed from the homepage immediately." / Confirm: "Delete Testimonial" (destructive-styled) |
| Destructive confirmation — remove partner/client logo | Title: "Remove this logo?" / Body: "This logo will be removed from the homepage's {Brand Partners / Corporate Clients} section immediately." / Confirm: "Remove" (destructive-styled) |

**Public homepage empty-state rule (default, not explicitly required by REQUIREMENTS.md but applied consistently):** Every new section independently hides entirely (renders nothing — no placeholder, no "coming soon" copy) when it has zero underlying admin-entered content, extending D-07's explicit Brand Partners/Corporate Clients rule to Hero Carousel, Why Choose Us, Featured Packages Grid, and Testimonials as well. This avoids a broken-looking blank section on day one before the admin has populated content, and avoids ever needing public-facing empty-state copy for marketing sections. The Embedded Inquiry Form section always renders (it has no "empty" state — it's a static form).
