<objective>
## Phase Goal

The homepage gains a hero carousel and admin-editable content sections -- value props, a featured packages grid, customer testimonials, an embedded inquiry form, and conditional Brand Partners/Corporate Clients logo sections -- all within the existing locked brand system.

(Same phase-level goal as 06-01-PLAN.md.)

## This Plan

Build the remaining 3 tabs of `/admin/content`: Why Choose Us, Testimonials, and Partners & Clients. Unlike 06-05's Hero Slides tab, none of these need drag-reorder or slide-type branching -- they are the simplest possible CRUD surfaces (2-4 flat fields each), all mirroring `account-form.tsx` + `users-table.tsx`'s exact Dialog-wraps-Form-then-list shape near-verbatim. Bundled into one plan because all 3 are the same shape repeated 3 times with different field sets -- splitting them into 3 separate plans would add coordination overhead with no parallelism benefit (they'd all be wave 3 anyway, all depending only on 06-02). Depends on 06-02 (needs `createValueProp`/`createTestimonial`/`createPartner` and friends, plus `uploadSiteContentImage`/`readFileAsBase64` for testimonial photos and partner logos).

**Deliberate scope decision (Claude's Discretion, documented per RESEARCH.md's own note):** value props, testimonials, and partners get NO drag-reorder UI this phase -- new items simply append at the end via `sort_order` computed server-side (06-02). Only hero slides (06-05) got the explicit "reorder slides" requirement (HOME-01); REQUIREMENTS.md states no equivalent reorder requirement for HOME-02/04/05/06.

Purpose: Give Admin/Staff with `can_manage_packages` full add/edit/delete control over value props, testimonials, and both partner/client logo lists.
Output: 10 new files under `components/admin/content/`, ready for 06-08 to mount inside the `/admin/content` Tabs page.
</objective>
