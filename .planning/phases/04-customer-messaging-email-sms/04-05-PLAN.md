<objective>
## Phase Goal

**As a** TravelSentro Admin or Staff member, **I want to** proactively reach out to customers individually or in bulk via email and SMS, with opt-outs respected and every message logged to CRM history, **so that** the business can follow up on leads without risking spam complaints, provider suspension, or losing a record of what was said.

(Same phase-level user story as 04-01/04-02/04-03/04-04-PLAN.md.)

## This Plan

Closes 04-UAT.md Test 3 (blocker): "Send an individual SMS... Failed, saw an error toast and no SMS message was sent." The debug session at `.planning/debug/sms-send-fails.md` root-caused this to two compounding issues: (1) `SEMAPHORE_API_KEY`/`SEMAPHORE_SENDER_NAME` were never actually provisioned in `.env.local` — the exact gap 04-02/04-03/04-04-PLAN.md each already flagged and deferred to end-of-phase human verification — and (2) Semaphore returns its "invalid apikey" validation error as HTTP 200 (not 4xx/5xx), so `lib/sms/semaphore.ts`'s `if (!res.ok) throw` never fires; the failure is only caught incidentally when `sendSingleSms()` tries to array-destructure the resulting plain error object and throws a `TypeError`. 04-REVIEW.md's IN-04 finding independently flagged the same file's missing `SEMAPHORE_API_KEY` runtime guard.

This plan does what's automatable — hardening `lib/sms/semaphore.ts` to explicitly detect both failure modes and give `actions/messages.ts` real diagnostic visibility into them — and hands off what genuinely isn't: creating a real Semaphore account and getting a sender name approved has no CLI/API path, so provisioning the actual credentials is a `checkpoint:human-action`.

Purpose: Turn an incidental, hard-to-diagnose SMS failure path into an explicit, diagnosable one, and get real working Semaphore credentials in place so MSG-02/MSG-04 actually function end-to-end.
Output: A hardened `lib/sms/semaphore.ts` + diagnostic logging in `actions/messages.ts`, a regression-proof verification script, and a working real SMS send confirmed via 04-UAT.md Test 3's replay.
</objective>
