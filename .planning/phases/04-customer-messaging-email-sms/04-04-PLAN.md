<objective>
## Phase Goal

**As a** TravelSentro Admin or Staff member, **I want to** proactively reach out to customers individually or in bulk via email and SMS, with opt-outs respected and every message logged to CRM history, **so that** the business can follow up on leads without risking spam complaints, provider suspension, or losing a record of what was said.

(Same phase-level user story as 04-01/04-02/04-03-PLAN.md.)

## This Plan

Close out MSG-05's remaining consent surfaces (the self-service unsubscribe link and the staff-manual toggle, D-02's two paths) and MSG-06's remaining "visible" half (04-03 already made sends "logged" — this plan makes them "visible" in the merged Activity timeline). This plan depends on 04-03 not because it needs new data, but because it touches the same three files (`actions/messages.ts`, `crm-detail.tsx`, `crm-table.tsx`) 04-03 just modified — a genuine file-overlap dependency, not a data dependency (the underlying `opted_out` column and `set_contact_opted_out()` RPC have been live since 04-01).

**Deliberate scope boundary — SMS inbound "STOP" keyword auto-opt-out is explicitly deferred, not built this phase.** 04-CONTEXT.md's Claude's-Discretion note frames this as "implement via Semaphore webhook if straightforward, otherwise defer entirely to the staff-manual toggle." This plan takes the deferral: no Semaphore webhook route is built. The staff-manual toggle (this plan's Task 1) is the only SMS opt-out path in v1, exactly as 04-RESEARCH.md's Deferred Ideas section anticipates — a customer who replies STOP to an SMS must be manually toggled by staff, same as any phone-requested opt-out.

**Routing decision (Route Handler vs. page.tsx):** 04-UI-SPEC.md left this open ("this contract defines its visual content regardless of implementation"). This plan implements `app/unsubscribe/page.tsx` as a Server Component rather than a Route Handler, because the endpoint's entire job is rendering visible HTML content (success/invalid confirmation cards) — a Route Handler would need to hand-construct an HTML `Response` string, which has no precedent anywhere in this all-React-Server-Component codebase. This mirrors the existing `app/admin/(dashboard)/crm/[id]/page.tsx` pattern of a Server Component performing a data operation (there: a `select`; here: a conditional `rpc` call) before rendering, not `app/api/inquiries/route.ts`'s Route Handler pattern (which exists because that endpoint is called by `fetch()`, never rendered).

Purpose: Deliver MSG-05's full consent story (both opt-out paths) and complete MSG-06 ("logged AND visible"), closing this phase's PH Data Privacy Act / email-provider-suspension risk flagged in STATE.md.
Output: A working public `/unsubscribe` page, a working manual opt-out toggle, and a unified Activity timeline showing every inquiry and message.
</objective>
