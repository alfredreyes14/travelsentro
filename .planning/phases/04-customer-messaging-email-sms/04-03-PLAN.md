<objective>
## Phase Goal

**As a** TravelSentro Admin or Staff member, **I want to** proactively reach out to customers individually or in bulk via email and SMS, with opt-outs respected and every message logged to CRM history, **so that** the business can follow up on leads without risking spam complaints, provider suspension, or losing a record of what was said.

(Same phase-level user story as 04-01/04-02-PLAN.md.)

## This Plan

Build the phase's core vertical slice: a Staff member can now actually compose and send an email or SMS — to one contact from the detail page, or to a multi-selected group from the contact list — and see it persisted as a `messages` row. This is the primary value proposition of Phase 4 (ROADMAP.md's success criteria #1 and #2), built as one plan because the individual and bulk paths deliberately share both the Server Action file and the compose dialog component (D-06/UI-SPEC's explicit "one shared component" instruction) — splitting them into separate plans would either duplicate the dialog or force the same file-overlap-driven sequential wave this single plan already achieves in one pass.

**Task ordering (interface-first):** Task 1 builds the "engine" (`actions/messages.ts` + `message-compose-dialog.tsx`) — the dialog's exact prop contract is specified here so Task 2 can wire consumers against a known interface. Task 2 wires the two entry points (`crm-table.tsx`'s bulk selection, `crm-detail.tsx`'s individual button) and extends both list/detail Server Component queries to fetch the new `opted_out` column.

**Deliberate scope boundary:** this plan does NOT build the opt-out manual toggle, the public unsubscribe route, or the merged Activity timeline — those are 04-04, which depends on this plan precisely because it touches the same three files (`actions/messages.ts`, `crm-detail.tsx`, `crm-table.tsx`) again. Individual sends in this plan are never blocked by `opted_out` (04-RESEARCH.md's Open Question 1 — MSG-05's exclusion wording is scoped to bulk sends only); the compose dialog surfaces an informational notice for an opted-out contact instead.

Purpose: Deliver MSG-01 through MSG-04 end-to-end (compose → send → logged), with MSG-05's bulk-side enforcement and MSG-06's logging built in from the start, not bolted on later.
Output: A working "Message" button on the contact detail page and a working "Message Selected" bulk flow on the contact list, both sending real email/SMS and logging every attempt.
</objective>
