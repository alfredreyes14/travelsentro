B2B Outreach Roadmap

How to build B2B cold outreach and a shared follow-up engine by extending the lead follow-ups already running in the CRM, instead of building a second system next to them.

Based on: staging at f82ce00 Spec: docs/b2b-outreach-spec.md Prepared: 23 Nov 2026
Approach

Extend what exists, then add cold email

Generalise the follow-up engine

Move the two hardcoded B2C sequences (no_reply, quote) into sequence tables. They must keep sending exactly as they do today.

Add a second sender

Resend stays for warm follow-ups. A Gmail sender on a separate outreach domain handles cold B2B email, because Resend's terms ban cold email.

Read replies

Today only Messenger replies and link clicks stop a sequence. Cold outreach also needs Gmail replies and bounces read, sorted by AI, and turned into stage moves.

Go-live gate

No cold email goes out in production until three things are true: the outreach inbox has finished its 2–3 week warm-up, the Gmail sender and its sending rules are done (phase 5), and reply and bounce handling is done (phase 6). Without phase 6, follow-ups would keep going to people who already replied.

Timeline

Eight weeks, two tracks

Assumes one developer. The business setup runs in parallel, and the inbox warm-up has to finish before cold sending starts. Week counts are estimates.

Phase 1

Generalise the follow-up engine

Store sequences as data instead of code. The current B2C follow-ups become the first two rows and must send exactly as before. Customers should see no difference.

Tasks
  • Migration: sequences, sequence_steps, sequence_enrollments, sequence_events. Access rules use has_module_permission('messages', …).
  • Database rules: one active enrollment per contact (a partial unique index), cold sequences must be B2B, and an enrolled contact's type must match the sequence's audience.
  • Seed no_reply and quote as warm B2C sequences with a stage trigger and 1, 3, 5 and 10-day gaps. Step text comes from templates.ts, using {{name}} and {{package}} merge tags.
  • Enroll contacts when they enter a stage, with a trigger on contacts (the same pattern as meta_outbox). Backfill enrollments for contacts already part-way through a sequence.
  • Add messages.sequence_id and messages.provider. Retire the check on follow_up_sequence.
  • Replace the hardcoded stage moves with a per-step "stage on send". Manual B2B follow-ups keep moving to Follow-up.
  • Add an EmailSender interface with the current Resend code as its only implementation.
  • Make remainingEmailQuota() count only Resend sends.
Reuse
  • lib/follow-ups/send.ts: one send, then a log entry, then the stage move.
  • list_due_follow_ups() logic: opt-out, clicked, 3-failure limit, 1-day staff pause.
  • advance_stage_for_follow_up() forward-only rules.
  • follow_up_progress view and follow-up-badge.tsx.
  • scripts/verify-follow-ups.ts as the regression check.
Done when verify-follow-ups passes, the daily cron's due list on staging data is the same before and after, and the CRM badges look the same.

Phases 2, 3

AI fit scoring, drafts and approval

Every cold first email is written by AI, then read and approved by a person before it can be sent.

Tasks
  • Score each imported lead from 1 to 5, with a one-line reason.
  • Draft a first email for leads scoring 3 or more. The draft says how we found them.
  • Create an enrollment with status draft holding the draft text.
  • An approval queue where staff can approve, edit or skip. Approving sets the status to approved.
  • A per-sequence "needs approval" setting. Warm sequences skip the queue.
Reuse
  • @anthropic-ai/sdk with structured output, as in lib/packages/extract-poster.ts.
  • Error handling for credits and keys from lib/packages/poster-error.ts.
Done when 20 imported leads give scores, drafts and a working approve, edit and skip flow.

Phases 0, 2, 4

Gmail sender and cold sending rules

Send approved cold emails from the outreach inbox, slowly and within the rules, in the same thread as earlier steps.

Tasks
  • A sequence_inboxes table holding the address, domain type, refresh token (encrypted with an app key), daily cap, ramp start and a paused flag.
  • An admin "Connect inbox" flow using Google OAuth, with permission to send and to read.
  • A GmailSender that sends plain text with a List-Unsubscribe header and keeps follow-ups in the same thread.
  • A new cron, /api/cron/sequences, scheduled */10 1-8 * * 1-5 (UTC), which is weekdays 9:00–16:50 Manila.
  • Each run sends at most one cold email per inbox. The next send is set 2–6 minutes later at random, so the gap is really the 10-minute cron interval or more.
  • A daily cap that starts at 5, adds 5 each week and stops at 30. Pause the inbox automatically if bounces pass 5% of the last 50 sends or anyone marks an email as spam.
  • Never send to opted-out contacts, bounced addresses, or anyone already in another sequence.
Reuse
  • lib/cron/authorize.ts and the follow-ups route's shape.
  • The signed unsubscribe link from lib/unsubscribe-token.ts, and /unsubscribe.
  • The messages log, so cold sends show on the contact timeline.
  • The FOLLOW_UPS_ENABLED pattern, as a new COLD_OUTREACH_ENABLED setting that is off by default.
Done when a test sequence sends to internal addresses within the window, keeps to the cap, threads correctly, and the unsubscribe link opts the contact out.

Phase 5

Replies, bounces and the funnel

When someone replies or an email bounces, stop the sequence, update the stage and tell the team.

Tasks
  • In the same cron, check the Gmail threads of active enrollments for new messages, and search for bounce notices (messages from mailer-daemon).
  • AI sorts each reply as interested, not interested, unsubscribe, out of office, bounce or unclear.
  • Act on the sequence's reply → stage map: stop, set opted_out, mark the email bounced, or keep going for out-of-office.
  • Save each reply as a sequence_events entry and show it in contact-activity.tsx.
  • Send a team alert for interested and unclear replies.
Reuse
  • lib/crm/notify-staff.ts and get_notification_recipients() for alerts.
  • set_contact_opted_out().
  • The Messenger poll's "check before sending" order from the follow-ups cron.
Done when each of the six reply types, sent from a test address, gives the expected stage and stops (or continues) the sequence.

Phase 2

Sequence editor and results page

Staff can create or change a B2B or B2C sequence without a code change, and see which sequences and lead sources get replies.

Editor
  • Settings: audience, type, trigger, inbox, steps, stage on send, reply → stage map, needs approval, stop-at stage.
  • Stage values are checked against isStageForType() in lib/crm/stage.ts.
  • Test: build a B2C warm sequence in the editor and run it on test data. Don't seed it.
Results
  • Sent, replied, interested, bounced, unsubscribed and reply rate.
  • Broken down by sequence, by lead source and by week.
  • Include the existing B2C sequences, which also have click data.
Done when a new sequence made in the editor sends with no deploy, and the results page numbers match messages and sequence_events.
